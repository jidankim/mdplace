# Normative Semantic Kernel operation and replay contract

This document is Normative Material for the `mdplace-spec/v1` Specification Package. The uppercase terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are to be interpreted as requirement strength. Canonical mdplace terms are defined only in [`CONTEXT.md`](../../../CONTEXT.md).

The accepted reconciliation in [issue #2](https://github.com/jidankim/mdplace/issues/2#issuecomment-5012541174) is an input to this contract. This document does not reopen that decision. In particular, immutable `.op.json` operation records replace draft JSONL history, the Semantic Kernel is the sole semantic writer, and Folder Projection, frontmatter, adapters, indexes, and caches remain derived or advisory consumers.

## REQ-SK-001: The canonical operation envelope is closed

This normative prose and the requirement catalog MUST retain the stable `REQ-SK-001` through `REQ-SK-007` identifiers and MUST use the canonical domain vocabulary in `CONTEXT.md`.

Every accepted semantic append MUST emit exactly one immutable canonical `OperationCommit` conforming to `contracts/schemas/semantic-operation.schema.json`. The record MUST carry stable operation identity, schema version, command identity, actor authority, declared operation kind, ordered base references, deterministic ordering material, a nonempty ordered event list, idempotency material, ordered preconditions, its closure receipt, and its operation digest. Every event MUST carry its own stable identity, zero-based ordinal, event kind, schema version, and kind-discriminated closed payload. Events are validated and applied atomically per `OperationCommit`: failure of any event preserves the pre-commit semantic state. Unknown fields, unknown operation kinds, unsupported schema versions, malformed records, torn records, and noncanonical JSON bytes MUST be rejected.

Canonical JSON is the JCS-compatible representation used by this closed schema: UTF-8 JSON with object keys sorted by UTF-16 code-unit order at every depth, arrays retained in declared order, no insignificant whitespace, and one trailing line feed for the published record. Lone Unicode surrogate code points are invalid input and MUST be rejected rather than escaped into a canonical record. `command_digest` MUST equal lowercase SHA-256 over the UTF-8 canonical JSON object containing `schema_id`, `command_id`, `operation_id`, `actor_authority`, `operation_kind`, `base_references`, `ordering`, `payload`, `idempotency_key`, and `preconditions`; it excludes the claimed digest. `operation_digest` MUST equal lowercase SHA-256 over the UTF-8 canonical JSON of the complete `OperationCommit` with only `operation_digest` omitted. A closure receipt binds the command, operation, sequence, outcome, and resulting semantic-state digest. Operation records are named `<operation_id>.op.json`; their identity never derives from a path, projection, cache row, or wall-clock timestamp.

## REQ-SK-002: Compare-and-append is serialized and fail-closed

The Semantic Kernel MUST serialize append attempts. `contracts/semantic-authorities.json` is the closed, package-bound authority registry. Authorization MUST match the complete `(actor_id, actor_kind, authority_ref)` tuple and the requested `append`, `replay`, `rebuild_view`, or `recover` capability; actor kind alone never grants authority. A new command is accepted only from an authorized actor, with a recomputed matching command digest, against the exact current semantic head, with contiguous ordering material, a recognized operation kind, satisfied preconditions, a new idempotency key, and an operation identity absent from the complete ordered operation-identity history. That history MUST contain exactly one unique identity for every committed sequence and end at the current semantic-head identity. Prior receipt identity fields MUST each be unique and MUST refer only to identities in that history. Success emits one canonical operation and one matching closure receipt. It MUST NOT emit a partial record, a second operation, or an independent semantic filesystem effect.

Rejection precedence is malformed or noncanonical input; unsupported schema or unknown operation kind; unauthorized actor; mismatched recomputed command digest; duplicate-incompatible idempotency material; stale or future base; noncontiguous ordering; failed precondition or illegal semantic transition. Every rejection is deterministic, preserves the semantic head and state, emits a closed Semantic Rejection receipt conforming to `contracts/schemas/semantic-receipt.schema.json`, and creates no canonical operation. A compatible duplicate returns the original receipt and creates no new operation even when the current head has advanced. A changed retry that retains its old digest is invalid; a changed retry with its newly recomputed digest is duplicate-incompatible.

## REQ-SK-003: Replay, snapshots, ordering, and views are deterministic

The first base reference MUST bind the exact semantic-head sequence, operation identity, and state digest. Later ordered base references MAY bind immutable input artifacts by identifier and digest. Ordering uses the monotonic sequence, predecessor operation identity, and stable sort key; wall-clock arrival order and filesystem enumeration order have no authority.

Replay MUST validate canonical bytes, schemas, event ordinals and versions, recomputed command and operation digests, exact authority tuples and capabilities, operation kinds, bases, ordering, preconditions, closure receipts, and idempotency before atomically applying an `OperationCommit`. A supplied record batch is transactional: any record failure preserves the pre-batch snapshot or genesis state and head. Sequence counters are closed integers from `0` through `256`; this permits four maximum-sized 64-record replay batches while bounding complete snapshot revalidation work. An operation that would advance beyond that supported maximum is schema-invalid. It MUST reproduce the same semantic state and Semantic Snapshot from the same canonical operation set and bound base inputs. A Semantic Snapshot MUST bind its head, state digest, complete ordered state entries, cumulative ordered operation and idempotency history including each operation digest and canonical operation record, and the digest of that history. Snapshot history MUST accept every supported sequence, including replay beyond one 64-record suffix batch. Snapshot replay MUST revalidate and replay those canonical history records before trusting the snapshot, then seed duplicate and operation identity checks from the verified history. Replay from a valid snapshot plus its suffix MUST equal full replay for both semantic state and idempotency decisions. A stale, noncanonical, or mismatched snapshot is rejected rather than trusted.

`contracts/semantic-operation-kinds.json` is the closed recognized-kind registry for this conformance foundation. A later Package Amendment MAY add a schema-bound kind without changing existing kinds. The recognized `compatibility_marker` kind has an explicit no-state replay effect and demonstrates forward compatibility; an unregistered kind is never skipped. Folder Projection, projections, frontmatter, adapters, indexes, and caches are rebuildable consumers and MUST NOT establish or append semantic truth. Exactly 30 manifest-owned stateful scenarios MUST exercise these replay, snapshot, ordering, forward-compatibility, and authority rules.

## REQ-SK-004: Stateful fixtures observe complete closure outcomes

The conformance manifest MUST own exactly 30 stateful scenarios, and every entry identified by a `FIX-SK-*` identifier, a `scenarios/semantic-kernel/` path, a `semantic_kernel` subject kind, or the Semantic Kernel scenario schema MUST be counted. Every counted entry MUST pair its manifest identifier and category, fixture-envelope identifier and category, path, subject kind, and schema correctly. Together they MUST cover valid append and replay, legal and illegal semantic removal, exact, stale, and future bases, compatible and incompatible duplicate commands, unknown operations, malformed and torn records, noncanonical records, snapshot equivalence, deterministic rebuild, recognized forward-compatible records, authority denial, illegal transitions, and crash recovery.

Every scenario oracle MUST expose its accepted append or deterministic rejection, canonical record identity or `none`, receipt, semantic state, Semantic Snapshot or replay result when applicable, rebuilt view when applicable, filesystem effects, terminal state, and illegal-transition result. Scenario inputs MUST be explicit; a validator MUST NOT infer actor authority, base state, ordering, idempotency, filesystem state, or recovery state from ambient process context.

## REQ-SK-005: Validation and evidence bind public behavior

The reference validator MUST validate operation and scenario schemas, the complete Semantic Kernel lifecycle table, exactly 30 manifest entries, all observable fixture dimensions, stable traceability, and `conformance/evidence/semantic-kernel-recovery-report.json`. It MUST assert public inputs, outputs, operations, receipts, filesystem effects, ordering, idempotency, Semantic Snapshots, replay, rebuild, and illegal transitions without inspecting a private implementation.

Machine evidence MUST bind every fixture byte digest and recomputed observable-result digest. Its structured claims MUST be recomputed from those results for replay and snapshot equivalence, deterministic rebuild, crash outcomes, and semantic-write denials. Rejection and recovery outcomes MUST contain closed structured receipts. Missing, extra, stale, malformed, self-asserted-only, or digest-incompatible evidence is non-pass.

## REQ-SK-006: The accepted reconciliation remains an input

Traceability MUST bind every REQ-SK requirement to accepted decision `DEC-002`, whose exact source is [issue #2](https://github.com/jidankim/mdplace/issues/2#issuecomment-5012541174) and whose use is `input_without_reopening`. This contract MUST NOT restore deprecated JSONL canonical history, path-derived truth, Unknown-like categories, multiple primary placements, coarse remote-processing authority, or generic taxonomy mutation authority.

## REQ-SK-007: Artifacts are specification and conformance only

This contract, its schemas, registry, lifecycle table, stateful Conformance Fixtures, conformance-only observer, traceability, and machine evidence MUST NOT implement or invoke production mdplace behavior. They MUST NOT start the mdplace Agent, host a Semantic Kernel, use the Control Channel, call the Vault Mutation Gate, mutate a vault, or grant semantic authority to a Capture Adapter, Intelligence Adapter, Folder Projection, projection, frontmatter bridge, index, or cache.

The validator MAY read declared Specification Package artifacts and emit its deterministic validation report on standard output. It MUST NOT write canonical operations, Semantic Snapshots, rebuilt views, receipts, or external files.

## Semantic Kernel lifecycle

`contracts/transitions/semantic-kernel-lifecycle.json` is complete over `ready` and `recovery_required` for `append_operation` and `recover_operation`. Append is legal only while ready. Recovery is legal only while recovery is required. Every denied row is a first-class illegal transition with unchanged semantic state and no canonical write.

## Release gate

The package MUST fail validation unless the operation envelope, receipt records, and supporting registries are closed, the lifecycle matrix is complete, `DEC-002` is exact, exactly 30 stateful scenarios are manifest-owned and passing, every required rejection code and denied lifecycle row is covered, replay and snapshot evidence agree including idempotency history, rebuild evidence is deterministic, the recovery report binds recomputed fixture results, and all adapter, projection, frontmatter, and cache write attempts are denied without a semantic write.

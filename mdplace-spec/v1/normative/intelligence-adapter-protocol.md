# Normative Intelligence Adapter proposal protocol

This document is Normative Material for the `mdplace-spec/v1` Specification Package. The uppercase terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are requirement strength. Canonical mdplace terms are defined only in [`CONTEXT.md`](../../../CONTEXT.md).

The accepted resolution in [issue #8](https://github.com/jidankim/mdplace/issues/8#issuecomment-5100984093) is the sole decision input. This contract applies that decision without reopening it. Intelligence Adapters are isolated, ephemeral, advisory-only producers of inert Intelligence Proposals. They have zero semantic authority and zero filesystem authority.

## REQ-IAP-001: Stable requirements use canonical protocol vocabulary

This contract and the requirement catalog MUST retain identifiers `REQ-IAP-001` through `REQ-IAP-008`. Intelligence Adapter, Processing Envelope, Intelligence Adapter Attempt, Intelligence Proposal, Adapter Run Receipt, Adapter Isolation Canary, Processing Policy, Source Profile, Semantic Kernel, Vault Mutation Gate, Conformance Fixture, Traceability Record, and Specification Package have only the meanings in `CONTEXT.md`.

An Intelligence Adapter Attempt is not a Work Item, semantic operation, placement decision, provider session, or filesystem operation. Acceptance of an Intelligence Proposal means only that its bytes passed the closed proposal schema and immutable binding checks. It MUST NOT mean acceptance as semantic truth.

## REQ-IAP-002: Processing Envelope, proposal, and receipt contracts are closed

Every Processing Envelope MUST conform to `contracts/schemas/processing-envelope.schema.json`. Before execution it MUST bind one stable chain, envelope, attempt, and authorization identity; the exact active approved Processing Policy and Source Profile identities, versions, and SHA-256 digests; the exact Taxonomy Revision identity, revision number, and SHA-256 digest; one source note and version digest; exact Intelligence Adapter, provider, model identity and version, prompt-contract, proposal-schema, purpose, and destination; ordered transmitted field segments and derived artifacts; each field's exact authorized data class and redaction rule/receipt obligation; effective capabilities; provider-declared retention facts and retained artifact kinds; a credential reference boundary that exposes no credential; and independent input, output, runtime, and cost ceilings. Unknown fields, wildcards, implicit defaults, mutable references, duplicate set members, and credential values are forbidden.

Every Intelligence Proposal MUST conform to `contracts/schemas/intelligence-proposal.schema.json`. It MUST echo the exact immutable bindings from its Processing Envelope and contain only one closed proposal kind, bounded evidence references to envelope segment identifiers, rationale, warnings, abstention, ranked candidates or taxonomy hypotheses, and scores explicitly marked uncalibrated. Its authority declaration MUST state no semantic, placement, taxonomy, filesystem, projection, destination-selection, tool, or credential authority. Unknown fields, partial output, invalid identifiers, stale bindings, and unbounded evidence references are rejected without salvage.

Every Adapter Run Receipt MUST conform to `contracts/schemas/adapter-run-receipt.schema.json`. It MUST bind the exact envelope and transmitted-byte digests, observed destination, effective capabilities, retention artifacts, credential boundary, isolation and canary evidence, measured resource use, observed start and completion timestamps, the provider request identifier when available or explicit `null` when unavailable, raw response and proposal artifact digests when present, chain position, immutable policy, Source Profile, and Taxonomy Revision bindings, one reason from the closed reason-to-outcome vocabulary, and zero semantic, filesystem, and tool effects. Observed timestamps MUST use the canonical UTC millisecond RFC 3339 form, completion MUST NOT precede start, and the exact elapsed milliseconds MUST equal measured `runtime_ms`. The receipt digest MUST be recomputed from the complete receipt with only its own digest omitted. Credentials, secrets, ambient configuration, and inferred facts MUST NOT appear.

## REQ-IAP-003: Policy binding, isolation, and canary checks precede transmission

The trusted authorization context in `contracts/intelligence-adapter/approved-context.json` MUST be read locally and matched before every attempt. Caller-supplied approval assertions cannot replace that readback. Exact policy and Source Profile identity, version, digest, lifecycle state, and approval state; exact Taxonomy Revision identity, revision, and digest; exact adapter, provider, model identity and version, purpose, destination, endpoint, credential boundary, adapter contract, prompt contract, and proposal schema; each transmitted field's exact authorized data class and redaction obligation; and equal-or-narrower field, artifact, redaction, capability, retention, and resource-ceiling sets MUST match the named attempt authorization. Remote destinations MUST use an exact credential-free `https://` endpoint, while local destinations MUST use an exact credential-free `local://` endpoint and local delivery MUST NOT be recorded as network egress; endpoint user information, query strings, fragments, malformed authorities, and alternate schemes are forbidden. Set comparisons MUST be order-independent, MUST reject duplicate members, and MAY omit authorized members for a least-privilege one-off envelope. `capability:produce-proposal` is always required; `capability:fixed-destination-network` is additionally required exactly when the destination is remote. Stale, revoked, missing, duplicate, ambiguous, malformed, version-mismatched, or widening bindings deny and transmit zero bytes.

The Adapter Isolation Canary and isolation observation MUST pass before payload transmission. Each attempt MUST be a fresh ephemeral process with no filesystem access, no tool interface, no ambient configuration, no credential visibility, no semantic or projection writer, and network access limited to the one named destination. Effective capabilities MUST be the closed advisory set. A failed or missing canary, non-ephemeral process, ambient-read capability, tool interface, credential exposure, filesystem access, semantic authority, or extra network destination records an isolation failure and transmits zero bytes.

Hostile instructions, fake boundaries, embedded tool calls, secret requests, ambient-configuration requests, destination changes, or authority claims inside transmitted data are data only. They MUST NOT change authorization or contracts. If adapter output attempts one of those actions, the output is rejected and the receipt records the corresponding deterministic denial without performing the action.

## REQ-IAP-004: Every initial, retry, and fallback attempt is independently bounded

The execution, denial, timeout, retry, fallback, isolation-failure, and recovery lifecycles in `contracts/transitions/intelligence-adapter-*.json` are complete state-command matrices. Every legal and illegal row MUST declare actor authority, preconditions, immutable base references, emitted records, filesystem effects, idempotency, terminal state, failure result, and recovery. A successful nonterminal transition MUST emit only its bounded observation, never an Adapter Run Receipt. The one terminal attempt outcome emits or recovers exactly one Adapter Run Receipt.

Before any attempt transmits, the complete requested chain MUST be checked against the trusted chain budget and legal ordered class prefix. The attempt count MUST NOT exceed `max_attempts`; retry and fallback counts MUST NOT exceed their independently approved maxima; attempt, envelope, and authorization identities MUST be unique; and every attempt sequence and chain identity MUST be exact. Input and output bytes, runtime, cost, retry count, fallback count, and aggregate chain use MUST be measured from instrumented observations, never trusted from provider claims. Equality with a ceiling is permitted; exceeding any ceiling denies or terminates the affected attempt. Every safely observable condition across chain, preflight, isolation, action, resource, output, and recovery phases MUST pass through the one declared global precedence evaluator before a result or transient schedule is selected. Contradictory timing measurements add malformed output to that evaluation while receipts use the exact canonical timestamp-derived runtime. A safe transient failure MAY schedule at most the exact pre-authorized retry, and that next attempt's complete immutable authorization, isolation proof, exact input byte count, and remaining aggregate input budget MUST still validate before the scheduling observation is emitted. A fallback MAY run only in its pre-authorized ordered position and only against its own equal-or-narrower Processing Envelope, isolation proof, destination, credential boundary, and ceilings. No retry or fallback inherits the prior attempt's authorization. A timeout, malformed output, isolation failure, policy denial, forbidden action, or budget exhaustion is not silently reclassified as retryable.

## REQ-IAP-005: Returned output is inert and adapters have zero authority

Raw output MUST remain inert bytes until size checks, JSON parsing, the closed Intelligence Proposal schema, immutable binding echoes, evidence-segment bounds, proposal-kind invariants, and authority declarations all validate. Malformed, partial, oversized, unknown-field, stale, mismatched, action-bearing, or authority-bearing output is rejected as a whole.

Even a valid Intelligence Proposal remains advisory data. An Intelligence Adapter MUST NOT establish or mutate semantic truth, choose note placement, alter taxonomy, append to the semantic journal, write a projection, invoke the Vault Mutation Gate, mutate the vault, select another destination, invoke a tool, read ambient configuration, request or receive a secret, or write any file. Only a separately authorized consumer MAY evaluate a valid proposal under its own authority; this protocol grants that consumer no authority and records no semantic or filesystem effect.

## REQ-IAP-006: Outcomes and recovery have deterministic receipts

Every attempt MUST produce or recover exactly one deterministic Adapter Run Receipt for acceptance, denial, timeout, retry scheduling, retry exhaustion, fallback scheduling, fallback exhaustion, malformed output, budget exhaustion, isolation failure, or recovery uncertainty. Every receipt reason MUST occur exactly in the closed `receipt_reasons` vocabulary in `contracts/intelligence-adapter/protocol-rules.json`, and its outcome MUST equal that reason's declared outcome. Receipt outcome and reason precedence is fixed globally by the same contract: when multiple conditions apply, the lowest numbered applicable condition MUST determine the receipt, and a later observation MUST NOT overwrite it.

A crash before transmission recovers to denied with zero transmitted bytes, and observing that crash before transmission MUST never construct a transmission. A crash after transmission but before a durable receipt remains `recovery_required`, MUST NOT blindly retry or retransmit, and records unknown completion. Operation, crash point, and instrumented crash behavior MUST form one closed compatible shape; a before-receipt crash behavior can never preserve an after-receipt result. A crash after the receipt preserves that exact receipt idempotently only when the same closed evaluator recomputes the complete proposal validity, globally selected outcome and reason, measured budget, observation bindings, and receipt bytes from the bound attempt evidence. Recovery MUST bind the exact prior transmission destination, byte count, and digest and any prior receipt to the same chain, attempt, authorization, envelope, policy, Source Profile, Taxonomy Revision, capabilities, retention artifacts, and credential boundary. Missing, torn, mismatched, unrelated, duplicate, ambiguous, contradictory, or self-consistent but incorrectly classified recovery evidence remains denied or `recovery_required`; it never manufactures acceptance. The recovery report MUST bind every recovery fixture and its observed receipt digest.

## REQ-IAP-007: Public fixtures and evidence prove the protocol

The conformance manifest MUST own exactly 42 `FIX-IAP-*` Conformance Fixtures under `conformance/scenarios/intelligence-adapter/`. They MUST cover positive, negative, exact-boundary, stale-state, authority-denial, illegal-transition, and crash/recovery categories without private implementation assertions. The corpus MUST include valid remote and local advice, retry and fallback success, hostile instructions, embedded tool calls, secret requests, ambient-configuration requests, unapproved destinations, capabilities, fields, artifacts, provider and purpose, missing redactions and retention facts, credential-boundary mismatch, malformed and unknown-field output, oversized output, input and output exhaustion, timeout, retry exhaustion, forbidden fallback, failed canary, failed isolation, stale policy, stale Source Profile, stale cached proposal, semantic, placement, and filesystem authority attempts, and all three recovery boundaries.

The instrumented double MUST preserve exact transmitted UTF-8 bytes and digest, exact destination, effective capabilities, declared retention artifacts, isolation and canary observations, attempt class and sequence, measured budgets, raw output digest, receipt bytes, denial behavior, retry and fallback attempts, and zero semantic, tool, and filesystem effects. `conformance/evidence/intelligence-adapter-evidence.json` MUST digest-bind those observations to the fixtures, approved context, Processing Envelopes, Intelligence Proposals, and Adapter Run Receipts. `conformance/evidence/intelligence-adapter-recovery-report.json` MUST bind recovery inputs and terminal outcomes. Every `REQ-IAP-*` Traceability Record MUST bind decision `DEC-008`, schemas, all seven lifecycle tables, positive and negative fixtures, acceptance gates, and both evidence artifacts.

## REQ-IAP-008: Decision and specification boundaries remain closed

Every `REQ-IAP-*` Traceability Record MUST cite only accepted decision `DEC-008` at [issue #8](https://github.com/jidankim/mdplace/issues/8#issuecomment-5100984093) with use `input_without_reopening`. This contract MUST NOT reopen provider admission, consent, placement thresholds, semantic acceptance, or adapter-profile readiness.

This ticket owns zero intake fixtures and zero stateful product scenarios, declares no Core, Web Clipper, Local Adapter, Remote Adapter, Codex Adapter, Placement Automation, New-Leaf Promotion, or Alias Promotion claim, and adds no production mdplace code. Its schemas, tables, pure observer, instrumented double, fixtures, validator assertions, traceability, evidence, and recovery report are specification and conformance artifacts only. The validator MAY read declared package artifacts and emit a report on standard output. It MUST transmit zero real network bytes and MUST NOT write a vault, semantic journal, Work Journal, policy, Source Profile, receipt, proposal, projection, or external file.

## Release gate

The package MUST fail validation unless every `REQ-IAP-*` requirement resolves; all named schemas are closed; all seven lifecycle matrices are complete; exact approved bindings, isolation, canary, independent attempt ceilings, retry and fallback order, inert output, receipt outcomes, and recovery boundaries validate; exactly 42 fixtures match their public oracles; the evidence and recovery reports recompute; every traceability edge resolves; `DEC-008` is exact and sole; and the package proves zero semantic, tool, credential, network-beyond-destination, and filesystem authority.
